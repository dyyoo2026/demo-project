### 발견한 문제 (코드 쪽 버그로 판단)

1. **50,000원 정확히일 때 무료배송이 안 됩니다** (`src/cart/pricing.ts:53`)
   - JSDoc에는 "할인 후 상품 금액이 50,000원 **이상**이면 무료배송"이라고 되어 있는데, 코드는 `>`로 비교합니다.
   - 50,000원 주문 → 기대값은 배송비 0원 / 총 50,000원, 실제로는 배송비 3,000원 / 총 53,000원입니다.
   - 수정 제안: `merchandiseTotal >= FREE_SHIPPING_THRESHOLD`

2. **PERCENT 쿠폰 할인액이 부동소수점 오차 때문에 1원 적게 나옵니다** (`src/cart/pricing.ts:46`)
   - `afterMembership * (coupon.percent / 100)`에서 `35 / 100 = 0.35`가 정확히 표현되지 않아서, `11000 * 0.35 = 3849.9999…`가 되고 `Math.floor`를 거치면 3,849가 됩니다.
   - 11,000원에 35% 쿠폰 → 기대값은 할인 3,850원, 실제로는 3,849원입니다. 이렇게 나눠떨어지는 금액에서도 1원이 깎입니다. 29, 35, 57, 58, 69, 70% 같은 할인율에서 흔하게 생깁니다.
   - 수정 제안: 곱셈을 먼저 하고 나중에 나누기 → `Math.floor((afterMembership * coupon.percent) / 100)` (정수끼리 곱하므로 오차가 없습니다)
   - 멤버십 할인율(3%, 5%)은 소계 1~1,000,000원 전 구간을 확인했는데 같은 문제가 없었습니다.

코드를 고치면 해당 `it.fails` 테스트가 빨간색으로 바뀝니다. 그때 `it.fails`를 `it`으로 바꿔 주시면 됩니다.

### 커버한 동작
- **수량 검증:** 0, -1, 1.5, NaN이면 `RangeError`를 던지고 메시지에 sku와 수량이 들어갑니다. 앞의 항목이 정상이어도 뒤의 잘못된 항목을 잡아냅니다.
- **소계:** 여러 항목의 단가 × 수량 합계를 계산하고, 전체 결과 객체를 비교합니다.
- **빈 장바구니:** GOLD 등급에 쿠폰이 있어도 모든 금액이 0원입니다 (배송비 포함).
- **멤버십 할인:**
  - 등급을 생략하면 BASIC으로 처리합니다.
  - BASIC / SILVER / GOLD 할인율이 맞게 적용되고, 원 단위 미만은 절사합니다 (33,333원 기준).
- **쿠폰:**
  - PERCENT 쿠폰은 멤버십 할인 *후* 금액에 적용되고 원 단위 미만은 절사합니다.
  - FIXED 쿠폰은 쿠폰 금액만큼 차감합니다.
  - FIXED 쿠폰 금액이 상품 금액보다 크면 상품 금액까지만 차감합니다.
  - 할인 후 금액이 `minOrderAmount`와 정확히 같으면 쿠폰을 적용합니다.
  - 소계는 최소 주문 금액을 넘어도 멤버십 할인 후 금액이 모자라면 쿠폰을 적용하지 않습니다.
- **배송비:**
  - 50,001원이면 무료, 49,999원이면 3,000원입니다.
  - 무료배송 기준은 소계가 아니라 멤버십과 쿠폰 할인을 모두 적용한 뒤의 금액입니다.

### 애매한 부분 / 커버하지 않은 부분
- **0원짜리 상품만 담긴 장바구니:** 코드는 `subtotal === 0`이면 빈 장바구니로 보고 배송비 0원을 반환합니다. 그런데 문서에는 "빈 장바구니는 배송비도 0원"이라고만 되어 있습니다. 사은품처럼 0원 상품만 있는 주문에 배송비를 받아야 하는지 정해 주세요. 어느 쪽이 맞는지 알 수 없어서 테스트로 고정하지 않았습니다.
- **검증 로직이 없는 입력:** 음수 단가, 0% 미만이나 100% 초과 쿠폰, 음수 FIXED 쿠폰 금액은 코드에 검증이 없습니다. 명세에도 정의되어 있지 않아서 테스트하지 않았습니다. 필요하면 검증을 추가하는 것을 고려해 보세요.
