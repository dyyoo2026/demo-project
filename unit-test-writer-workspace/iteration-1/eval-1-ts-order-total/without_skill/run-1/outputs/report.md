`calculateOrderTotal` 유닛 테스트를 `src/cart/pricing.test.ts`에 작성했습니다. 테스트는 30개입니다. 28개는 통과하고 **2개는 실패**하는데, 둘 다 테스트가 틀린 게 아니라 코드가 JSDoc에 적힌 규칙과 다르게 동작해서 실패합니다.

## 발견한 버그 2건

**1. 정확히 50,000원일 때 배송비가 붙습니다** (`pricing.ts:53`)
JSDoc에는 "50,000원 **이상**이면 무료배송"이라고 되어 있지만 코드는 `>`로 비교합니다. 그래서 50,000원짜리 주문에 배송비 3,000원이 붙습니다.
```ts
// 현재
const shippingFee = merchandiseTotal > FREE_SHIPPING_THRESHOLD ? 0 : SHIPPING_FEE;
// 수정안
const shippingFee = merchandiseTotal >= FREE_SHIPPING_THRESHOLD ? 0 : SHIPPING_FEE;
```

**2. PERCENT 쿠폰이 1원 덜 할인되는 경우가 있습니다** (`pricing.ts:46`)
`percent / 100`을 먼저 계산하면 부동소수점 오차가 생깁니다. 예를 들어 2,800원에 35% 쿠폰을 적용하면 `979.9999…`가 나오고, 이를 절사해서 980원이 아닌 979원이 됩니다. 1~100% 쿠폰 전체를 확인해 보니 29, 35, 41, 47, 57, 58, 69, 70, 82, 94%에서 이 문제가 생깁니다. 반면 멤버십 할인(3%, 5%)은 소계 200,000원까지 확인했을 때 문제가 없었습니다.
```ts
// 현재
couponDiscount = Math.floor(afterMembership * (coupon.percent / 100));
// 수정안: 정수끼리 먼저 곱한 뒤 나눈다
couponDiscount = Math.floor((afterMembership * coupon.percent) / 100);
```

위 두 줄을 임시로 고쳐서 돌려 보면 32개 테스트(기존 `format.test.ts` 2개 포함)가 모두 통과합니다. 확인 후 원래 코드로 되돌려 두었습니다.

## 제가 내린 판단
- **소스 코드는 수정하지 않았습니다.** 요청하신 건 테스트 작성이었고, 문서와 코드 중 어느 쪽이 의도한 동작인지는 직접 판단하셔야 합니다. 그래서 테스트는 JSDoc 명세를 기준으로 작성했고, 실패하는 테스트 2개도 결과가 잘 보이도록 그대로 두었습니다.
- 만약 `>`(50,000원 초과)가 의도한 동작이라면 테스트를 고칠 게 아니라 JSDoc을 고쳐야 하고, 그다음 "정확히 50,000원" 테스트의 기대값을 바꿔야 합니다.
- 버그를 바로 고칠 수 없는데 테스트 스위트를 초록색으로 유지해야 한다면, 실패하는 두 테스트를 `it.fails(...)`로 바꾸는 방법이 있습니다. 이렇게 해 두면 버그를 고쳤을 때 테스트가 실패해서 표시를 지워야 한다는 걸 알 수 있습니다.

## 테스트 범위
- **소계**: 단가 × 수량의 합, 등급을 생략하면 BASIC으로 처리
- **수량 검증**: 0, 음수, 소수, NaN, Infinity는 RangeError(메시지에 sku 포함), 상품 여러 개 중 하나만 잘못돼도 에러, 수량 1은 허용
- **빈 장바구니**: 모든 금액 0원이고, 등급이나 쿠폰이 있어도 마찬가지
- **멤버십 할인**: BASIC 0%, SILVER 3%, GOLD 5%, 원 단위 미만 절사
- **쿠폰**: PERCENT는 멤버십 할인 후 금액에 적용되고 원 단위 미만 절사, FIXED는 할인 후 금액을 넘지 않음, `minOrderAmount`는 금액이 같을 때 적용되고 미만일 때 적용되지 않으며 소계가 아닌 멤버십 할인 후 금액으로 판단
- **배송비**: 49,999원, 50,000원, 50,001원에서 확인, 소계가 아닌 할인 후 금액으로 판단
- **통합 시나리오**: 멤버십 → 쿠폰 → 배송비 순서로 모두 적용

기대값은 상수(`FREE_SHIPPING_THRESHOLD` 등)를 가져다 쓰지 않고 숫자로 직접 적었습니다. 그래야 누가 상수를 잘못 바꿔도 테스트에서 잡힙니다. `npm run typecheck`도 통과합니다.

실행: `npx vitest run src/cart/pricing.test.ts`
