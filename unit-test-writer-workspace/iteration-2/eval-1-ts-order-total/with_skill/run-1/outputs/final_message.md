## 발견한 버그

**1. 정확히 50,000원이면 무료배송이어야 하는데 배송비 3,000원이 붙음** (`src/cart/pricing.ts:53`)
- JSDoc 규칙 4는 "할인 후 상품 금액이 50,000원 **이상**이면 무료배송"인데, 코드는 `merchandiseTotal > FREE_SHIPPING_THRESHOLD`로 비교합니다.
- 기대값은 `shippingFee: 0`, `total: 50,000`이고, 실제로는 `shippingFee: 3,000`, `total: 53,000`이 나옵니다.
- 고치는 방법: `>`를 `>=`로 바꾸면 됩니다.
- 고친 뒤에는 테스트 `'상품 금액이 정확히 50,000원이면 무료배송이다 (BUG: ...)'`에서 `it.fails`를 `it`으로 바꿔 주세요.

**2. PERCENT 쿠폰 할인액이 부동소수점 오차로 1원 적게 나옴** (`src/cart/pricing.ts:46`)
- `afterMembership * (coupon.percent / 100)`을 계산할 때 오차가 생깁니다. 예를 들어 22,000원에 35% 쿠폰을 쓰면 7,699.999…가 나오고, 이걸 절사해서 7,699원이 됩니다. 기대값은 7,700원입니다.
- 29·35·41·47·57·58·69·70·82·94% 쿠폰에서 이런 일이 생깁니다. 금액이 딱 떨어지는 경우에도 생깁니다.
- 고치는 방법: `Math.floor((afterMembership * coupon.percent) / 100)`처럼 정수 곱셈을 먼저 하세요.
- 고친 뒤에는 테스트 `'PERCENT 쿠폰 할인액이 정확히 정수면 그대로 할인한다 (BUG: ...)'`에서 `it.fails`를 `it`으로 바꿔 주세요.

`it.fails`는 코드를 고치는 순간 빨간색으로 바뀌어서, 표시를 지우라고 알려 줍니다. 원본은 그대로 두고 임시 복사본에서 확인해 봤는데, 위 두 가지 수정을 적용하면 각각 해당 테스트가 뒤집혔습니다.

## 테스트 작성 결과
- **파일:** `src/cart/pricing.test.ts` (27개). 기존 `format.test.ts`처럼 같은 폴더에 두고, 테스트 이름은 한국어로 썼습니다.
- **실행:** `npx vitest run` → 29개 통과(기존 2개 포함, 그중 2개는 known-bug `it.fails`), 실패 0개. `npm run typecheck`도 통과했습니다.
- **테스트 강도:** 역시 임시 복사본에서, 그럴듯한 실수를 8가지 일부러 넣어 봤습니다(경계 비교 바꾸기, 절사를 반올림으로 바꾸기, 쿠폰 최소금액을 소계와 비교하기, FIXED 상한 빼기 등). 8가지 모두 테스트가 잡아냈습니다.

**커버한 동작**
- **수량 검증:** 0, -1, 1.5, NaN, Infinity일 때 `RangeError`가 납니다. 두 번째 이후 상품이 잘못돼도 에러가 나고, 메시지에 해당 SKU가 들어갑니다.
- **소계:** 빈 장바구니는 모든 금액이 0원입니다. 여러 상품의 단가 × 수량을 합산합니다.
- **멤버십:** 등급을 생략하면 BASIC입니다. 할인율은 BASIC 0%, SILVER 3%, GOLD 5%이고, 원 단위 미만은 절사합니다.
- **쿠폰:**
  - 멤버십 할인 후 금액에 적용됩니다.
  - PERCENT 쿠폰은 원 단위 미만을 절사합니다.
  - FIXED 쿠폰은 할인 후 금액을 넘지 않습니다. 이 경우 상품 금액은 0원이 되고 배송비 3,000원만 남습니다.
  - `minOrderAmount`는 금액이 같으면 적용하고 1원 모자라면 적용하지 않습니다. 소계가 아니라 멤버십 할인 후 금액과 비교합니다.
- **배송비:** 49,999원이면 3,000원, 50,001원이면 0원입니다. 무료배송 여부는 모든 할인을 뺀 금액으로 판단합니다.

## 모호한 부분 (확인 부탁드립니다)
- **단가 0원 상품만 담긴 경우:** 장바구니가 비어 있지 않아도 소계가 0원이면, 코드는 빈 장바구니처럼 배송비 0원을 돌려줍니다(`pricing.ts:36`). JSDoc은 "빈 장바구니"만 말하고 있어서 의도가 분명하지 않습니다. 일단 지금 동작대로 테스트를 고정하고 주석을 달아 두었습니다. 무료 상품만 담아도 배송비를 받아야 한다면 이 테스트를 바꿔 주세요.

## 커버하지 않은 부분
- 음수 단가, 0% 미만이나 100% 초과 PERCENT 쿠폰, 음수 FIXED 쿠폰은 코드도 검증하지 않고 문서에도 정해진 내용이 없어서 테스트하지 않았습니다. 막아야 하는 입력이라면 검증 로직을 추가하는 걸 고려해 보세요.
