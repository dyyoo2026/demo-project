`src/cart/pricing.test.ts`에 `calculateOrderTotal` 테스트 32개를 작성했습니다. 기존 `format.test.ts`와 같은 Vitest 스타일로 썼고 테스트 이름은 한국어입니다. 실행해 보니 **30개는 통과하고 2개는 실패합니다.** 실패하는 2개는 테스트를 잘못 쓴 게 아니라, 코드가 JSDoc에 적힌 규칙과 다르게 동작하는 버그를 잡은 것입니다.

## 발견한 버그 2건

**1. 정확히 50,000원일 때 무료배송이 안 됩니다** (`pricing.ts` 53행)
JSDoc에는 "50,000원 **이상**이면 무료배송"이라고 되어 있는데, 코드는 `>`로 비교합니다. 그래서 할인 후 상품 금액이 딱 50,000원이면 배송비 3,000원이 붙습니다.
```ts
// 현재
const shippingFee = merchandiseTotal > FREE_SHIPPING_THRESHOLD ? 0 : SHIPPING_FEE;
// 수정안
const shippingFee = merchandiseTotal >= FREE_SHIPPING_THRESHOLD ? 0 : SHIPPING_FEE;
```

**2. PERCENT 쿠폰이 부동소수점 오차로 1원 덜 할인됩니다** (`pricing.ts` 46행)
`afterMembership * (percent / 100)` 순서로 계산하기 때문에 생깁니다. 예를 들어 11,000 × 0.35는 3849.9999…가 되고, 이를 절사하면 3,850원이 아니라 3,849원이 됩니다. 1~100% 범위를 모두 돌려 보니 29, 35, 41, 47, 57, 58, 69, 70, 82, 94%에서 이 문제가 생겼습니다. 정수끼리 먼저 곱하고 나중에 나누면 해결됩니다.
```ts
couponDiscount = Math.floor((afterMembership * coupon.percent) / 100);
```
멤버십 할인율(3%, 5%)은 같은 방식으로 전 범위를 확인했고 오차가 없었습니다.

## 제가 정한 것들
- **소스 코드는 고치지 않았습니다.** 요청하신 건 테스트 작성이라서 `pricing.ts`는 그대로 두었습니다. 그래서 지금은 `npx vitest run`이 실패로 끝납니다. 위 두 줄을 고치면 전부 통과합니다. 의도된 동작이라면 테스트를 반대로 바꾸거나 `it.fails`로 표시해 드릴 수도 있습니다.
- **기대값은 JSDoc 규칙을 기준으로 잡았습니다.** 현재 코드가 내는 값을 그대로 기대값으로 쓰지 않았습니다.
- **FIXED 쿠폰이 상품 금액 전체를 덮는 경우**(할인 후 상품 금액 0원)에는 배송비 3,000원이 부과되는 것으로 테스트했습니다. 문서에서 배송비 0원 예외는 "빈 장바구니"만 언급하기 때문입니다.
- 단가가 0원인 상품만 담긴 장바구니는 동작이 명세되어 있지 않아 테스트하지 않았습니다. 지금 코드는 이 경우를 빈 장바구니처럼 배송비 0원으로 처리합니다.

## 테스트 범위
- **소계:** 여러 상품의 단가 × 수량 합산, 등급 생략 시 BASIC 적용
- **수량 검증:** 0, 음수, 소수, NaN, Infinity일 때 `RangeError`. 에러 메시지에 SKU 포함, 여러 상품 중 하나만 잘못돼도 에러, 단가 0원 상품도 검증
- **빈 장바구니:** 모든 금액 0원. 등급이나 쿠폰이 있어도 0원
- **멤버십 할인:** BASIC/SILVER/GOLD 할인율, 원 단위 미만 절사
- **쿠폰:**
  - PERCENT는 멤버십 할인 후 금액에 적용되고 절사됨
  - FIXED는 할인 후 금액을 넘지 않음
  - `minOrderAmount`는 같은 금액이면 적용, 1원 모자라면 미적용, 소계가 아닌 멤버십 할인 후 금액으로 판단
- **배송비:** 49,999 / 50,000 / 50,001원 경계, 할인 후 금액으로 판단
- **전체 조합:** 멤버십 + 쿠폰 + 무료배송 시나리오

실행 결과: `npx vitest run` 기준 테스트 34개 중 32개 통과, 2개 실패(위 버그 2건)입니다. `tsc --noEmit`은 통과합니다.
